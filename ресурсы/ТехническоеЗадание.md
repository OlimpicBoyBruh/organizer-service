# Техническое задание
## Приложение-органайзер учебных материалов

### 1. Общие сведения
#### 1.1 Назначение документа
Настоящее техническое задание (ТЗ) определяет требования и порядок разработки программного обеспечения "Органайзер учебных материалов".

#### 1.2 Наименование проекта
Полное наименование: "Приложение-органайзер учебных материалов"
Краткое наименование: "Органайзер материалов"

#### 1.3 Назначение и цели создания системы
**Назначение системы:**
Обеспечение пользователей (студентов и преподавателей) инструментом для организации учебных материалов по различным дисциплинам с возможностью быстрого поиска и доступа к нужной информации.

**Цели создания системы:**
- Систематизация учебных материалов по дисциплинам
- Упрощение поиска нужных материалов
- Организация файлов различных форматов в единой системе
- Повышение эффективности образовательного процесса

### 2. Характеристика объекта автоматизации
Объектом автоматизации является процесс работы с учебными материалами, включающий хранение, поиск и доступ к файлам разных форматов.

**Роли пользователей:**
1. **Студент** - основной пользователь, работающий с учебными материалами
2. **Преподаватель** - пользователь, который добавляет и организует учебные материалы для студентов

### 4. Требования к системе

#### 4.1. Функциональные требования

##### 4.1.1. Управление дисциплинами
- Система должна позволять создавать новые дисциплины с уникальными названиями
- Система должна отображать список всех созданных дисциплин в виде древовидной структуры
- Система должна позволять выбирать дисциплину из списка для просмотра её материалов

##### 4.1.2. Управление материалами
- Система должна позволять добавлять новые материалы с указанием названия, даты и тегов
- Система должна связывать каждый материал с определенной дисциплиной
- Система должна отображать список материалов для выбранной дисциплины
- Система должна показывать детальную информацию о выбранном материале
- Система должна обеспечивать поиск материалов по названию
- Система должна обеспечивать поиск материалов по тегам
- Система должна обеспечивать поиск материалов по дате

##### 4.1.3. Управление файлами
- Система должна позволять прикреплять файлы к материалам
- Система должна позволять прикреплять ссылки на внешние ресурсы
- Система должна отображать список прикрепленных файлов и ссылок для выбранного материала
- Система должна обеспечивать открытие прикрепленных файлов в соответствующих приложениях
- Система должна обеспечивать открытие прикрепленных ссылок в браузере
- Система должна поддерживать удаление прикрепленных файлов и ссылок

##### 4.1.4. Хранение данных
- Система должна хранить файлы в локальной директории ресурсов приложения
- Система должна сохранять информацию о материалах и дисциплинах между запусками

#### 4.2. Нефункциональные требования

##### 4.2.1. Требования к пользовательскому интерфейсу
- Интерфейс должен быть интуитивно понятным для пользователей без специальной подготовки
- Интерфейс должен обеспечивать одновременное отображение списка дисциплин, материалов и деталей выбранного материала
- Время отклика интерфейса на действия пользователя не должно превышать 1 секунду
- Интерфейс должен предоставлять визуальную обратную связь при выполнении длительных операций

##### 4.2.2. Технические требования
- Система должна работать под управлением ОС Windows 10 и выше
- Для работы системы должна быть установлена Java версии 17 или выше
- Система должна работать на компьютерах с оперативной памятью не менее 4 ГБ
- Система не должна потреблять более 500 МБ оперативной памяти при нормальном режиме работы

##### 4.2.3. Требования к надежности
- Система должна корректно обрабатывать ошибки и представлять пользователю понятные сообщения
- Система должна предотвращать потерю данных при сбоях в работе приложения
- Система должна создавать резервные копии данных при критических операциях
- Вероятность отказа системы при нормальной работе не должна превышать 0.01%

##### 4.2.4. Требования к безопасности
- Система должна обеспечивать сохранность прикрепленных файлов
- Система должна предотвращать несанкционированный доступ к данным

### 5. Сценарии использования

#### Сценарий 1: Добавление новой дисциплины и материала
**Роль:** Студент/Преподаватель
1. Пользователь запускает приложение
2. В левой части интерфейса вводит название новой дисциплины в поле ввода
3. Нажимает кнопку "Добавить"
4. Выбирает созданную дисциплину в дереве дисциплин
5. Нажимает кнопку "Добавить новый материал"
6. Вводит название материала и теги
7. Система создает материал и связывает его с выбранной дисциплиной
8. Пользователь видит созданный материал в списке материалов дисциплины

#### Сценарий 2: Прикрепление файла к материалу
**Роль:** Студент/Преподаватель
1. Пользователь выбирает дисциплину в дереве
2. Выбирает материал из списка
3. Нажимает кнопку "Прикрепить файл"
4. В открывшемся диалоговом окне выбирает файл
5. Нажимает "Открыть"
6. Система копирует файл в директорию ресурсов
7. Система создает вложение и связывает его с материалом
8. Пользователь видит прикрепленный файл в списке вложений

#### Сценарий 3: Поиск материала по тегам
**Роль:** Студент/Преподаватель
1. Пользователь вводит тег в поле "Поиск по тегу"
2. Нажимает кнопку "Поиск"
3. Система находит все материалы, содержащие указанный тег
4. Система отображает результаты поиска в списке материалов
5. Пользователь выбирает нужный материал из результатов
6. Система отображает детали выбранного материала и его вложения

### 6. Требования к программной реализации

#### 6.1. Архитектура приложения
Приложение должно быть реализовано с использованием архитектуры MVC (Model-View-Controller):
- **Model** - классы для представления дисциплин, материалов и вложений
- **View** - графический интерфейс, реализованный с помощью JavaFX и FXML
- **Controller** - логика работы приложения, обработка действий пользователя

#### 6.2. Используемые технологии и библиотеки
- Java 17
- JavaFX для пользовательского интерфейса
- Spring Boot для управления зависимостями и компонентами
- Javafx-weaver для интеграции JavaFX и Spring Boot
- Apache PDFBox (опционально) для работы с PDF-файлами

#### 6.3. Структура проекта
Проект должен быть организован в соответствии с принципами Spring Boot:
```
src/main/java/ru/organaizersrv/uiorganizerapp/
├── config/                 # Конфигурационные классы
├── controller/             # Контроллеры
├── dao/                    # Классы доступа к данным
├── event/                  # Классы событий
├── exception/              # Исключения
├── model/                  # Модели данных
├── service/                # Сервисы
├── util/                   # Утилитные классы
```

#### 6.4. Тестирование
Для обеспечения качества приложения должны быть реализованы:
- Модульные тесты для проверки работы отдельных компонентов
- Интеграционные тесты для проверки взаимодействия компонентов
- Ручное тестирование пользовательского интерфейса
